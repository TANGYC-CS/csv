## 右键运行仍用 C:\Python311 的根因与修复（重要）
- 现象：右键「在终端中运行 Python 文件」执行 `& "C:\Python311\python.exe" ...`，报 `ModuleNotFoundError: cv2`。
- 根因：`python-envs` 扩展把已选解释器持久化在 **VS Code 工作区状态库** `%APPDATA%\Code\User\workspaceStorage\<hash>\state.vscdb` 的 ItemTable 里，键 `ms-python.vscode-python-envs`，内容形如 `{"...:system:WORKSPACE_SELECTED":{"f:\\计算机视觉":"c:\\Python311\\python.exe"}}`。该值优先级高于 settings.json 里的 `python.defaultInterpreterPath`（后者只是优先级 3），所以改配置无效。
- 对应 hash：根工作区 `F:\计算机视觉` = `c1d1468ca3e2341a366e0d0ffb8f5f76`；`1图像处理` = `2496abfecae16e606d83155ca15d8a03`（后者本来就是 Python37）。
- 修复：备份为 `state.vscdb.bak-20261113-1020`，用 sqlite3 把 WORKSPACE_SELECTED 改成 `f:\计算机视觉\Python37\python.exe`，并删除 `ms-python.python` 键里的 `lastKnownActiveInterpreter:F:\计算机视觉`（原值为 C:\Python311）。改完必须「重新加载窗口」才被读取。
- 踩坑：Git Bash 会对传给 python 的路径参数做转义/转换（`\\` 被吞成 `/`），改状态库的脚本要把反斜杠用 `os.sep` 在 Python 内部拼，不要从命令行传路径。
- 结论：以后遇到"改了默认解释器但 VS Code 不认"，先查 state.vscdb 的 WORKSPACE_SELECTED，而不是反复改 settings.json。

## 新增课件 05resize.py
- `2图像绘制与变换/05resize.py`：cv2.resize 两种用法——① dsize=(4*width, 2*height) 显式尺寸；② dsize=None + fx=1/2, fy=1/4 比例缩放。
- 依赖同目录图片 `1.jpeg`（用户尚未放入）。验证时在临时目录 `%TEMP%\cv_resize_check` 用 `1图像处理/cat.png` 转 jpeg 跑通，未污染课件目录。
- 实测数据（cat.png 330高×333宽）：dsize=(1320,666) → 结果 shape (666,1320,3)；fx/fy → shape (82,166,3)。
- 课件写法 `width, height = img.shape[:2]` 命名是反的：shape[:2] 是 (行/高, 列/宽)。因猫图接近正方形（330×333）肉眼看不出，但长宽比大的图会明显变形。dsize 参数顺序是 (宽,高)，与 shape 相反。
- 环境坑：OpenCV 3.4.2 的 `cv2.imread` 不支持中文路径（读 F:\计算机视觉\... 直接返回 None），须用 `cv2.imdecode(np.fromfile(path, np.uint8), cv2.IMREAD_COLOR)`；`imread` 只有传相对路径且 cwd 含中文时才碰巧可用。
- 后续修复：用户报 `AttributeError: 'NoneType' object has no attribute 'shape'`。两个原因叠加——① 课件目录里本来没有 `1.jpeg`（课程素材需自行放入）；② VS Code 右键运行时终端 cwd 是 `F:\计算机视觉` 而非文件所在目录，相对路径 `'1.jpeg'` 找不到。
- 处理方式：用 cat.png 生成了 `2图像绘制与变换/1.jpeg`（imencode + tofile 绕过中文路径问题）；在 05resize.py 顶部加 `os.chdir(os.path.dirname(os.path.abspath(__file__)))` 让 cwd 无关化。已验证从 `F:\计算机视觉`、`C:\` 两个 cwd 运行都正常，输出 `(330, 333, 3)`。
- 通用经验：本机所有课件脚本只要用相对路径引用同目录素材，都要防“右键运行 cwd 是工作区根”这个坑。

## 新增课件 07rotate.py
- `2图像绘制与变换/07rotate.py`：`cv2.getRotationMatrix2D` 取 2x3 旋转矩阵 + `cv2.warpAffine` 做仿射旋转，角度 45（正数=逆时针），缩放 1。已加 `os.chdir(__file__ 所在目录)`。
- 实测：img.shape (330,333,3)，M = [[0.707,0.707,-69.41],[-0.707,0.707,165.44]]。
- 课件 `width, height = img.shape[:2]` 的比值问题在这里后果更明显：旋转中心实际传了 (165,166.5)，真实中心应是 (166.5,165)；`warpAffine` 的 dsize 传 (330,333) 导致输出宽高互换，结果 shape 变成 (333,330,3)。猫图接近正方所以只差 1.5px 看不出来。
- 对照实验（800x300 长条图）：按课件写法 w=300/h=800，旋转中心跑到 (150,400)（y 已超出画面高 300），dsize (300,800) 把横图输出成竖图，画面被裁掉大半 —— 可作为讲解"shape 顺序"的反面教材。
- 文件编号沿用课件 07（06 号课件的截图用户尚未提供，位置留空）。
- 备注：用 cv2 存预览图时不要再手动 cvtColor 成 RGB，`imencode` 本身就按 BGR 处理，转了会二次串色。
